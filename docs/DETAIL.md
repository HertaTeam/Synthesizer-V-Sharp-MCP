# Synthesizer V 写歌（MCP）

把一个本地 MCP 服务器接进 DSH，让模型用工具把「旋律 + 歌词」写成真正的
Synthesizer V Studio 工程文件，再交给编辑器试听和导出。

## 能力

- **发现声库**：`list_voices` 读取本机安装的声库（`voice.nofs` 头部），返回名称、版本、
  支持语种和文件夹。
- **写工程**：`write_song` 用 `notes` 数组或 `notation` 简谱生成 `.svp`，可指定速度、拍号、
  声库、演唱语言、轨道名和 Vocal Mode。文件直接是编辑器自己的格式（svp version 153）。
- **读工程**：`read_song` 解析 `.svp`，返回速度、拍号、声库、音符数、歌词、音域、时长，
  可选返回逐音符。
- **打开工程**：`open_song` 用本机的 `synthv-sharp.exe` 打开工程；编辑器是独立进程。
- **查状态**：`app_status` 返回编辑器是否在运行、程序路径和默认输出目录。

## 简谱写法的约定

每个音写作 `音高:拍数:歌词`，空格分隔，`|` 是可选的隔线：

```
C4:1:你 D4:0.5:好 R:0.5 | E4:2:啊 -:1:啊
```

拍数按四分音符计；`R` 是休止，`-` 沿用前一个音高再唱一个音节；音高支持 `C4`、`F#3`、
`Bb2` 或 MIDI 数字。

## 边界

- 不渲染音频。Synthesizer V Studio 没有对外渲染接口，导出仍是在编辑器里点一次。
- 不实时修改已经打开的工程：工具只生成和读取文件，改动请重新 `write_song`。
- 非默认声库的语种、版本来自声库文件头部推断；个别声库的描述符可能不准，`read_song`
  可以看到写进去的描述符，必要时在编辑器里手动换声库。
- 需要 Node.js（`cordis.patch.yml` 里写的是本机 Node 路径），编辑器路径默认取本包的
  上一级目录，可用 `SV_APP_DIR` 覆盖。
